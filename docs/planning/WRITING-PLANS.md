# Writing Nexus plans

Use Full Plan Mode (a living written plan) for substantive multi-phase work; tiny fixes use lightweight inline tracking. Read PLAN-TEMPLATE.md before a new plan. One plan represents one logical Jira-sized chunk. Use 3–10 incremental, testable phases. Follow TDD where practical. Update the SAME file as tasks, status, scope, review, validation, questions or lessons change. Never create separate phase/completion reports. Mark child tasks and phase checkboxes together. Record actual automated validation and exact implementation SHAs. No manual testing requirements unless requested or automation cannot verify the task. Keep Lessons empty until an actual repair, correction, fallback or useful discovery occurs. Update the roadmap as the continuity index; stop before the next plan without authorization.
